# Лабораторная работа №3

Тема: интеграционное тестирование проектов и работа с тестовыми заглушками.

## Стек

- Python 3.x
- `unittest` + `unittest.mock` (стандартная библиотека)
- `sqlite3` (стандартная библиотека)
- `abc` — абстрактные базовые классы как интерфейсы

## Архитектура

Контроллер собирает четыре независимые зависимости и реализует сквозной сценарий.

| Класс | Файл | Роль |
|---|---|---|
| `TriangleCalculator` | `src/calculator.py` | вычисления из ЛР1 |
| `TriangleRepository` | `src/repository.py` | SQLite: `add`, `get`, `delete`, `count` |
| `UserInterface` (ABC) | `src/user_interface.py` | интерфейс ввода |
| `ConsoleUserInterface` | `src/user_interface.py` | реализация через `input()` |
| `ExternalService` (ABC) | `src/external_service.py` | интерфейс сторонней зависимости |
| `NotificationService` | `src/external_service.py` | имитация отправки данных |
| `Controller` | `src/controller.py` | сквозной сценарий |

## Сценарий работы `Controller.run()`

1. Запрашиваются три стороны через `UserInterface`.
2. Выполняется поиск записи в БД по трём длинам:
   - запись найдена → результат берётся из БД, источник `из БД`;
   - запись не найдена → результат считается `TriangleCalculator`, сохраняется в БД, источник `вычислено`.
3. Строка-результат отправляется через `ExternalService`.
4. Возвращается кортеж `(тип, координаты, текст ошибки, источник)`.

### Интеграционные тесты и заглушки

`tests/test_controller_integration.py` проверяет совместную работу настоящих
`TriangleCalculator` и `TriangleRepository` (SQLite в памяти) с **заглушками**
на границах системы:

```python
self.ui_mock = Mock(spec=UserInterface)          # имитация ввода пользователя
self.external_mock = Mock(spec=ExternalService)  # имитация внешнего сервера
```

Заглушки позволяют проверить, что контроллер обращается к вводу ровно один раз
(`assert_called_once_with`) и отправляет результат ровно один раз
(`assert_called_once`), не поднимая реального терминала и не обращаясь к сети.
